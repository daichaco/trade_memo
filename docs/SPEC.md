# 仕様書 v0.1

## 1. コンセプト
「ルール設定 → 取得価格を入れると損切り・利確ラインを自動算出 → 資金から株数を算出 → そのままトレードメモとして保存 → 決済後に、損切りを守れたかを振り返る」を一続きにする。
既存アプリは損益記録が中心で、エントリー前の計画と振り返りが分断されている。そこが差別化ポイント。

## 2. 画面（タブ：計画 / 保有 / 振り返り / 設定）
画面イメージはデザインキャンバス「トレードメモ 画面イメージ」を参照。

1. **新規トレード計画**：銘柄、取得予定価格、損切り（決め方を選ぶ＋根拠メモ）、利確（決め方を選ぶ）を入力 → ラインの図、株数、必要資金、損切り時の損失、利確時の利益を表示 →「この計画でエントリーを記録」
2. **買い増し計画**：同じ銘柄の保有ロット一覧と、残りの損失枠を表示 → 新しいロットの価格・損切り・利確を入力 → 株数と、買い増し後の平均取得単価・全ロット損切り時の損失を表示
3. **保有中**：銘柄の合計（保有株数、平均取得単価、含み損益、全ロット損切り時の損失）＋ロットごとのカード（取得・損切り・利確、当初の損切り、損切りされた場合の損益、現在値から各ラインまでの距離）＋日付つきメモ
4. **決済の記録**：ロットの計画を表示 → 決済価格と株数を入力 → 自動判定と、はみ出した額 → 判定の手動修正と理由メモ
5. **振り返り**：期間（今月 / 3か月 / 全期間）、損切り遵守率、ルール違反で余計に失った額、決済の内訳、損切りが遅れた取引の一覧
6. **設定**：総資金、1回の許容損失（%）、損切り・利確の初期値と決め方、株数の単位、「守れた」とみなす幅

現在値は手入力（保有画面で更新）。

## 3. 計算仕様

### 3.1 記号
- C：総資金（設定）
- r：1回の許容損失率（設定、例 2%）
- R = C × r：1回の許容損失額
- E：取得（予定）価格、S：損切り価格、T：利確価格
- u：株数の単位（100 または 1）

### 3.2 損切りラインの決め方
- %指定：S = E × (1 − p)
- 金額指定（1株あたり）：S = E − a
- 価格を直接：S を入力（根拠メモを任意で記録）
- 条件：S < E。満たさないときは計算せずエラー表示

### 3.3 利確ラインの決め方
- %指定：T = E × (1 + q)
- 価格を直接：T を入力
- リスクリワード：T = E + k × (E − S)（k は倍率、例 2.0）
- 条件：T > E。リスクリワード比 (T − E) / (E − S) は常に表示

### 3.4 株数
1. 1株あたりの損失 d = E − S
2. 損失枠 L = R − 既存ロットで使用中の損失（3.5）
3. 損失から出る株数 qR = floor(L / d)
4. 買付余力 B = C − 保有中の全ロットの取得金額の合計（qty × entry の合計、全銘柄）
5. 資金から出る株数 qB = floor(B / E)
6. 株数 q = floor(min(qR, qB) / u) × u
7. 表示：必要資金 q × E、損切り時の損失 q × d、利確時の利益 q × (T − E)、資金に対するリスク率
8. qB < qR のときは「買付余力で上限に達しています。実際のリスクは ◯円です」と警告
9. q = 0 のとき：100株単位なら「この条件では買えません（1株単位なら ◯株）」を表示

単位は設定の値を初期値とし、計画画面で切り替えられる。銘柄ごとの上書きも可能（設定でオン/オフ）。

### 3.5 既存ロットの損失（同じ銘柄の買い増し）
- 損切りラインはロットごとに別々に持つ
- ロット i の損切り時の損失 = max(0, (e_i − s_i)) × q_i
  - 損切りを取得価格以上に引き上げたロットは 0（利益分を枠に足し戻すことはしない）
- 使用中の損失 = 同じ銘柄の保有中ロットの合計
- 他の銘柄の損失は枠に影響しない（R は1銘柄＝1トレードあたり）。他銘柄は買付余力（3.4 の 4）にだけ影響する
- 買い増し後の平均取得単価 = Σ(q_i × e_i) / Σq_i

### 3.6 損切りラインの変更（引き上げ）
- 保有中にロットの損切り価格を編集できる。当初の値（initialStop）と変更履歴（日時・旧値・新値・メモ）を残す
- 振り返りの判定は「決済時点の損切りライン」を基準にする

### 3.7 決済の自動判定
ロットの損切り S、利確 T、決済価格 X、守れたとみなす幅 tol（設定、円）として：
- X ≥ T → **利確**
- |X − S| ≤ tol → **守れた**
- X < S − tol → **遅れた**。はみ出した額 = (S − X) × 決済株数
- それ以外（S + tol < X < T）→ **計画外**（ライン到達前の手仕舞い）
- ユーザーは判定を手動で変更できる。自動判定と最終判定の両方を保存

v1 では1ロットを一度に全株決済のみ（部分決済は v2）。

### 3.8 振り返りの集計（期間は決済日で絞る）
- 損切り遵守率 = 守れた ÷ (守れた + 遅れた)。分母 0 のときは「—」
- ルール違反で余計に失った額 = 遅れたロットのはみ出した額の合計
- 内訳：守れた / 遅れた / 利確 / 計画外 の件数
- 損切りが遅れた取引の一覧（銘柄、ロット、はみ出した額、理由メモ）

## 4. 計算例（ユニットテストにする）
設定：C = 1,000,000、r = 2%（R = 20,000）、u = 100

**例1：新規**　E = 1,000、S = 950、利確 RR 2.0、他銘柄の保有 300,000
- d = 50、qR = 400、B = 700,000、qB = 700 → q = **400株**
- T = 1,100、必要資金 400,000、損切り時 −20,000、利確時 +40,000

**例2：1株単位**　例1と同じで u = 1、E = 1,000、S = 937 → d = 63、qR = 317 → q = **317株**（u = 100 なら 300株）

**例3：買い増し**　同じ銘柄で 1回目 400株 @1,000（損切りを 1,000 へ引き上げ済み）、他銘柄の保有なし、E = 1,060、S = 1,020
- 使用中の損失 0 → L = 20,000、d = 40、qR = 500
- B = 1,000,000 − 400,000 = 600,000、qB = 566 → q = **500株**
- 平均取得単価 = (400×1,000 + 500×1,060) / 900 = 1,033.33…

**例4：買い増しで枠が残っていない**　1回目 400株 @1,000、損切り 950（使用中 20,000）→ L = 0 → q = **0株**、「損失枠が残っていません」

**例5：資金で頭打ち**　C = 1,000,000、他銘柄 900,000、E = 1,000、S = 950 → qR = 400、qB = 100 → q = **100株**、警告、実際のリスク 5,000

**例6：決済判定**（S = 1,020、T = 1,140、tol = 2、200株）
- X = 1,019 → 守れた
- X = 1,012 → 遅れた、はみ出した額 1,600
- X = 1,140 → 利確
- X = 1,080 → 計画外

## 5. データモデル（SwiftData の目安）
- **AppSettings**：capital, riskPercent, defaultStopMethod, defaultStopValue, defaultTakeProfitMethod, defaultTakeProfitValue, defaultUnit, allowPerSymbolUnit, keptTolerance
- **Position**（銘柄）：name, code, unitOverride?, currentPrice?, lots, notes
- **Lot**：position, index（1回目, 2回目…）, quantity, entryPrice, entryDate, stopMethod, stopPrice, initialStopPrice, stopMemo, takeProfitMethod, takeProfitPrice, status（open / closed）, stopChanges, exit?
- **StopChange**：lot, date, oldPrice, newPrice, memo
- **ExitRecord**：lot, date, price, quantity, autoJudgment, judgment, overshootAmount, reason
- **NoteEntry**：position, date, text

## 6. 進め方（マイルストーン）
1. Xcode プロジェクトの雛形、`Domain/` の計算ロジック＋ユニットテスト（4章の例をすべて通す）
2. SwiftData モデル、設定画面
3. 新規トレード計画 → エントリー記録
4. 保有中画面（ロットのカード、損切りの編集、メモ）、買い増し計画
5. 決済の記録と自動判定
6. 振り返り画面
7. 仕上げ（空の状態、エラー表示、ダークモード、Dynamic Type、アイコン）

## 7. v1 でやらないこと
株価の自動取得、証券会社連携、部分決済、空売り、手数料・税金、iCloud 同期、課金（収益化の方法は別途検討）
